# Entity Relationship Diagrams (ERDs)

You should, of course, prefer to update existing Lucid documents if one exists, but if it doesn't, you can start by creating a document and using the Entity shape to represent each table. Use line endings to represent relationships properly, and avoid overlapping lines. When working in an existing document, you should be aware of the styles present already in the document and aim to keep the styles on any new shapes or lines consistent.

## Legend

An ERD usually speaks for itself, but if you feel the need to add more information, be sure to put it in a separate shape, with a distinct style so it's clear it's not part of the ERD. Rather than stating assumptions within the document, you should either clarify with the user before creating the document, or clarify after and update the document accordingly. Anything smaller, like a comment about a table, can go in a sticky note to make it clear it's additional data about that table.
